# Mac 菜单栏日历应用设计（极致轻量版）

日期：2026-02-23

## 1. 目标与范围

### 目标
- 做一个 macOS 菜单栏日历应用（AppKit）
- 应用体积尽可能小、后台内存占用尽可能小
- 交互体验尽量接近 Windows 任务栏日历（点击即出月历弹层）
- 支持中国节假日显示

### 范围（本阶段）
- 菜单栏图标点击弹出月历
- 月视图网格中节假日显示 `假` 角标
- 首次启动下载节假日并本地缓存
- 提供手动刷新按钮
- 菜单栏显示模式可选：固定图标 / 今日日期

### 非目标（本阶段不做）
- 日程管理、提醒、待办集成
- 多国家节假日
- 后台定时自动刷新

## 2. 架构与组件

### 应用形态
- 使用 `LSUIElement` 的菜单栏应用（无 Dock 图标）
- 入口为 `NSStatusItem`
- 点击后通过 `NSPopover` 展示月历内容

### 核心组件
- `StatusBarController`
  - 管理菜单栏按钮与点击行为
  - 支持两种显示模式：固定图标 / 今日日期
- `PopoverController`
  - 管理弹层显示/关闭与生命周期
- `CalendarView`
  - 渲染月视图网格
  - 当天高亮、选中态
  - 节假日日期格显示 `假` 角标
- `HolidayService`
  - 首次下载节假日数据
  - 处理手动刷新
- `HolidayCacheStore`
  - 节假日缓存读写（JSON）
- `SettingsStore`
  - 保存用户偏好（菜单栏显示模式）

### 轻量化策略
- 不引入数据库、WebView、重型第三方框架
- 不做后台轮询，仅首次与手动刷新联网
- 按需加载当前月份展示数据

## 3. 数据流与刷新逻辑

### 首次启动
1. 读取本地缓存
2. 若有有效缓存：直接渲染月历 + `假` 标记
3. 若无缓存：先渲染基础月历（不阻塞 UI），后台拉取节假日
4. 拉取成功后：写缓存并刷新当前月视图
5. 拉取失败：保留基础月历并显示轻提示

### 手动刷新
1. 用户点击 `刷新`
2. 按钮进入 loading，防重入
3. 成功：更新缓存并刷新视图，提示“已更新”
4. 失败：保留旧缓存，提示失败原因

### 最小数据模型
- `HolidayRecord`
  - `date: String`（YYYY-MM-DD）
  - `isHoliday: Bool`
  - `name: String?`（预留）

月历渲染只依赖 `isHoliday` 来决定是否显示 `假`。

### 缓存策略
- 路径：`Application Support/<bundle-id>/holidays-<year>.json`
- 年度拆分存储
- 元信息：`lastUpdatedAt`、`sourceVersion`
- 刷新失败不清空旧缓存

## 4. 错误处理与边界场景

### 网络错误
- 首次下载失败：可用普通月历，不显示 `假`
- 手动刷新失败：继续使用旧缓存
- 使用非阻断轻提示，不弹窗打断

### 数据错误
- 返回格式异常视为本次更新失败
- 保留旧缓存
- 记录本地调试日志

### 日期与时区
- 节假日匹配按 `Asia/Shanghai`
- 菜单栏今日日期按本机当前日期显示

### 性能边界
- 仅渲染当前可见月份
- 缓存按年小文件读取
- 不启常驻网络任务

### 体验兜底
- 无网但有缓存：照常显示 `假`
- 无网且无缓存：显示普通月历 + 轻提示
- 刷新按钮始终可用

## 5. 测试与验收标准

### 功能验收
- 菜单栏可见，点击弹出月历
- 可切换固定图标 / 今日日期，且持久化
- 节假日日期格显示 `假`
- 首次无缓存会下载，成功后出现 `假`
- 刷新按钮可更新数据

### 可靠性验收
- 断网有缓存：正常显示
- 断网无缓存：不崩溃并提示
- 服务端异常：不崩溃、不污染旧缓存

### 性能验收
- 冷启动后可快速交互
- 常驻内存低占用
- 刷新过程不阻塞主线程

### 回归验收
- 跨月后 `假` 标记正确
- 当用户选择“今日日期”模式时，跨天显示正确
- 重启后设置和缓存可恢复

## 6. 后续实施边界

进入实施阶段后，优先顺序：
1. 菜单栏与弹层骨架
2. 月视图与 `假` 标记渲染
3. 首次拉取 + 缓存
4. 刷新按钮与错误提示
5. 设置持久化与回归测试
